# Third-Party-Risk-Management-TPRM
ACOVNA.SRL case study
Portfolio disclosure: This repository documents a training/case-study vendor risk assessment. Findings and recommendations are based on the project materials provided, not independently verified vendor security claims. No real-world vendor approval or remediation is implied.
This project evaluates third-party software requests for ACOVNA.SRL, a social media marketing and analytics company that processes customer information, behavioral analytics, and marketing performance data. The objective was to balance business productivity with cybersecurity, privacy, and access-management requirements before vendor onboarding.
I reviewed the supplied vendor security evidence, recorded issues, risks and control gaps, prepared follow-up security questions, and documented risk-based onboarding recommendations in a central vendor tracking spreadsheet.
Objectives
- Evaluate the security posture and business justification of requested third-party tools.
- Identify assurance gaps and potential vulnerabilities using available vendor documentation.
- Assess authentication, access lifecycle, data retention, and information security governance.
- Prioritize follow-up questions, remediation evidence, and vendor onboarding decisions.
- Compare proposed tools with the organization's existing tool inventory to identify possible duplication.
- Assessment approach
- Business context and tool overlap: Read the vendor request list, business justification, and existing tool inventory.
- Security evidence review: Evaluated SOC 2 Type II information, penetration testing evidence, information security policies, data retention/deletion, and SSO/MFA capabilities.
- Issue, risk, and gap identification: Distinguished observed concerns, potential business/security impacts, and missing or unverified controls.
- Vendor due diligence: Drafted targeted security questions requesting missing documents, remediation status, retesting results, and compensating controls.
- Risk-based recommendations: Documented preliminary priorities and whether further validation or remediation should precede onboarding.
